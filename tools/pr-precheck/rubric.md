# Rubric: is this pull request ready to submit?

Every check below reads the PR itself against its plan, its issue, and its
repo's stated standards: what the diff changes, what the evidence shows, what
the description claims. None of them grade how the write-up looks. A terse
description over a matching diff with decisive evidence passes every check; a
polished one over a diff that does something else fails.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every changed file and every hunk in the diff, read against the plan's scope, its in-scope and not-in-scope lines, its files line, and any deviation or deferral note (evidence guide, "Plan fidelity") | Pass if every hunk does work the plan commits to (the fix itself, its tests, a doc or changelog line for the changed behavior, or something a deviation note records) AND every piece of work the plan commits to is in the diff or is explicitly deferred in the plan's notes and restated in the description. Fail if any hunk adds work the plan does not commit to: a new flag, option, or setting; a rename or refactor pass; a rewrite of a function the fix did not need; edits to an unrelated file, or to text or behavior outside the fix (reworded help text, other error messages), even when the extra work is adjacent or harmless and even when the core fix is right. Fail if a piece of planned work is missing with no note. | required |
| description-matches-diff | Every claim in the PR description (and title) about what the change does, what it touches, or how faithful it is to the plan ("implements the plan exactly", "no changes outside X", "docs now document Y"), read against the diff (evidence guide, "Plan fidelity") | Pass if every such claim is true of the diff, and any deferral or deviation the plan records is stated in the description. Fail if the description claims something the diff does not contain (a docs update, a test, a file) or claims fidelity ("exactly as planned", "no other changes") over a diff that does more. | required |
| decisive-evidence | The test-evidence section (and any before/after in the description), read against the plan's test plan and the issue's repro steps (evidence guide, "Test evidence") | Pass if ALL of: (1) the issue's failing case, as the plan's test plan names it, is re-run on the branch with an observable before AND after (an exit code, printed output, a value, a behavior) that differs between broken and fixed code, or an expected-before is stated next to a shown after; (2) every failure mode of the reported bug that the test plan names (each repro, each way the bug shows up) is re-run with its after shown, not just one of them; a check of new behavior the fix adds (a warning, a message, a control that stays unchanged) passes when the evidence states its observed result, without pasted output; (3) the run exercises the path the fix changed, not a control or neighboring path that never broke; (4) the outcome of the repo's own test suite or checks is shown (a named command with its result). Fail on "tested locally", "works on my machine", "works now", or "tests pass" with no named observable; on evidence that only re-runs a control or an unchanged path; on a test-plan case left un-run; or on no suite outcome. | required |
| clean-diff | Every added and removed line in the diff, and the commit list (evidence guide, "Diff quality") | Pass if every hunk is part of the fix or its tests, docs, or changelog, so a reviewer reads only the change. Adding the one import the fix uses is fine. Fail if the diff adds any of: a debug print or log (active or commented out), a commented-out block or earlier attempt, dead code (an unused function or variable, anything behind `allow(dead_code)` or an `_unused` name), a new TODO/FIXME, formatting-only or whitespace-only churn, a run of lines removed and re-added unchanged with no changed line among them (pure re-print churn), or an import reorganization the fix did not need. Lines removed and re-added unchanged around a real change in the same block (a multi-line call where one argument changes) are diff context, not churn. | required |
| template-and-disclosure | The repo-facts block's PR template, contributing asks, and contribution policy, read against the description, title, diff, and commits (evidence guide, "Standards and comms") | Pass if every ask the repo states as required for a PR is met: each template section or required checklist item present with real content (an issue-link line such as `closes #N` or `fixes #N` with the actual number when asked; a changelog or whatsnew entry in the diff when asked; tests with behavior changes when asked), AND, if the repo's AI policy requires disclosing AI use in the PR or "in any form", the description has a sentence stating that AI was used, which tool, and how much. Treat every package as AI-assisted work, so a missing disclosure never reads as "no AI was used". A policy that only asks that text be the contributor's own words, or no stated AI policy, needs no disclosure sentence. Fail if any stated required ask is visibly absent or left as an unfilled template placeholder. | required |
| unknowns-stated | The description's notes on limits, untested platforms, or deferred work, read against what the evidence does not cover (evidence guide, "Standards and comms") | Pass if the description names what it did not verify or deliberately left out, or the change is small enough that no real unknown exists. Fail if it claims certainty the evidence does not back ("cannot break anything", "fully tested on all platforms"). | preferred |

## Verdict rule

Accept only if all five required checks grade `pass`. Any required check graded
`fail` or `unclear` means reject: `unclear` counts as fail, because a PR the
grader cannot verify from the package is a PR a reviewer cannot verify either.
`unknowns-stated` is preferred: report it, but it never changes the verdict.
An honest shortfall is not a fail: work the plan defers, or a deviation the plan
records, that the description also states, passes `diff-matches-plan` and
`description-matches-diff`. The deciding check is the first required check, in
table order, that did not pass.
